### Что такое Iptables?

Это инструмент, с помощью которого мы говорим Linux:
- какой сетевой трафик разрешать
- какой блокировать
- и что вообще делать с пакетами

То есть по сути - это один из способов настроить firewall

Самое важное, что iptables не работает сам по себе, а управляет netfilter в ядре Linux

Можно приставить так:
netfilter - механизм внутри ядра
iptables - интерфейс, через который мы задаем ему правила

Например, приходит пакет:
- источник: 1.2.3.4
- назначение: наш сервер
- пор: 22
- протокол TCP

Linux прогоняет его через iptables
ACCEPT -> пропустить 
DROP -> выбросить
Это основная идея.

Теперь самое важное - chain и цепочка

Цепочка - это просто набор правил
Например:
- INPUT - трафик приходит на сервер
- OUTPUT - трафик уходит с этого сервера
- FORWARD - сервер не конечная точка, он пропускает пакет дальше

Теперь про tables

Таблица - это группа цепочек, объединенных по назначению

Самая важная для начала - filter. Она отвечает за пропустить пакет или заблокировать. И именно в ней находятся INPUT, OUTPUT, FORWARD

Теперь nat:

Эта таблица несколько блокирует пакеты, сколько меняет IP-адреса/порты в пакетах.

То есть private ip меняет на один публичный ip

Вот NAT и занимается этим преобразованием

Остальные таблицы:

- mangle - изменять отдельные поля пакетов
- raw - она используется для очень ранней обработки пакетов 
- security - дополнительные security-механизмы

Теперь как реально работает правило:
iptables -A INPUT -p tcp --dport 22 -j ACCEPT 

Читаем слева направо:
- -A INPUT - добавить правило в цепочку INPUT
- -p tcp - только tcp
- --dport 22 - destination port 22
- -j ACCEPT - разрешить 

То есть: если пакет приходит на этот сервер по TCP на порт 22 - разрешить

А если например:
iptables -A INPUT -p tcp --dport 22 DROP 
То в таком случае входящий TCP на порт 22 - выбросить

И ключевая логика iptables:
пакет приходит - попадает в нужную chain - правила проверяются сверху вниз - первое походящее правило срабатывает - ACCEPT / DROP / ДРУГОЕ ДЕЙСТВИЕ

Например, правила такие:

INPUT:
1. SSH 22 PORT -> ACCEPT
2. HTTP 80 PORT -> ACCEPT
3. Все остальное -> DROP

И например приходит пакет на 22: правило 1 совпало -> ACCEPT 
Приходит на 80: правило 1 не совпало, правило 2 совпало -> ACCEPT
Приходит на 5000: правило 1 не совпало, правило 2 не совпало, правило 3 совпало -> DROP

***iptables - последовательная проверка правил для сетевых пакетов***

### Возникает логичный вопрос: чем отличается firewall от iptables?

Если говорить техническим языком, то в самом ядре Linux живет модуль под названием netfilter - именно он занимается всей грязной работой: перехватывает пакеты, проверяет их, пропускает наружу или блокирует.

iptables - это программа/утилита, которая работает в пространстве пользователя, и отправляет команды напрямую в этот самый ядерный netfilter

ufw/firewalld (высокоуровневые фаерволы) - стоят еще на один шаг выше, они берут человеческие команды (вроде открой порт 80) и переводят их на сложный язык правил iptables, а iptables уже загружают их в ядро. 

И сейчас кстати в 2026 году: на замену iptables пришел nftables - он современнее, быстрее и лучше работает с процессором, но для нас как для пользователей ничего не изменилось. Эта замена произошла, так сказать под капотом.
