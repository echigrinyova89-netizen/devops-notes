### Что такое вообще модель OSI?

Это модель, которая условно делит сетевое взаимодействие на 7 уровней. Она нужна для того, чтобы можно было диагностировать проблему: например, проблема не в приложении, а на сетевом уровне или IP доступен, но TCP-порт закрыт.

То есть для DevOps - во многом это модель диагностики.

Когда мы открываем страницу в браузере, до того, как она реально появится в браузере участвует сразу несколько уровней.

УРОВНИ СВЕРХУ ВНИЗ:

7. APPLICATION (УРОВЕНЬ ПРИЛОЖЕНИЙ)
Здесь находятся протоколы, которыми непосредственно пользуются приложения.

HTTP
HTTPS
DNS
SSH
SMTP
FTP

6. PRESENTATION (ПРЕДСТАВИТЕЛЬНЫЙ УРОВЕНЬ)
Отвечает за предоставление данных.

- кодирование
- шифрование
- форматы данных
- сжатие

UTF-8
JSON
JPEG
TLS

Важный нюанс: в реальных современных сетях уровни 5-7 редко существуют настолько отдельно, как показывается классическая OSI.

5. SESSION (СЕАНСОВЫЙ УРОВЕНЬ)

Управляет сеансами между приложениями.

Например: установить взаимодействие, поддерживать его, завершить.

Но в современной практике - его также редко рассматривают отдельно. 

4. TRANSPORT (ТРАНСПОРТНЫЙ УРОВЕНЬ)

Один из самых важных для девопса.

Здесь: TCP, UDP, порты

Например: 

TCP 22 -> SSH
TCP 80 -> HTTP
TCP 443 -> HTTPS
UDP 53 -> DNS

Здесь важно понять разницу: IP отвечает на вопрос - на какой компьютер отправить данные, а порт отвечает на вопрос - какому приложению на этом компьютере передать данные?

Например: 192.168.1.10:22
Означает: 192.168.1.10 - сервер
22 - SSH-сервис на сервере

Для девопса L4 встречается постоянно. Например ситуация: ping работает, а ssh не подключился. Это уже сильная подсказка, что L3 вероятно, работает, а проблема может быть в L4 или выше.

3. NETWORK (СЕТЕВОЙ УРОВЕНЬ)
Это второй критически важный уровень.

Здесь работают:

-IP адреса
-маршрутизация
-подсети
-routes

Главный протокол: IP

Именно L3 отвечает за то, как пакет попадет из одной сети в другую.

Linux commans:
- ip addr
- ip route
- ping
- traceroute

2. DATA LINK (КАНАЛЬНЫЙ УРОВЕНЬ)
Здесь данные передаются уже внутри ЛОКАЛЬНОГО сегмента сети.

Основные понятия:

- Ethernet 
- MAC address
- frame
- switch
- ARP

1. PHYSICAL (ФИЗИЧЕСКИЙ УРОВЕНЬ)
Это физическая передача:

- кабель
- оптоволокно
- радиосигнал WI-FI
- электрический сигнал
- биты 0 и 1

ВАЖНАЯ ЧАСТЬ ДЛЯ ПОНИМАНИЯ:

7 - ЧТО ПРИЛОЖЕНИЕ ХОЧЕТ ПЕРЕДАТЬ
4 - КАКОМУ ПРОЦЕССУ И КАК НАДЕЖНО ПЕРЕДАТЬ
3 - НА КАКОЙ ХОСТ ОТПРАВИТЬ
2 - КАК ДОСТАВИТЬ СЛЕДУЮЩЕМУ УСТРОЙСТВУ
1 - ПЕРЕДАЧА БИТОВ

Инкапсуляция - каждый нижний уровень добавляет к данным свою служебную информацию, обычно заголовок (сверху вниз - от приложения к физическому)
Декинкапсуляция - снизу вверх (от физического до приложения)

### Почему для Девопса важно запомнить уровни - 3, 4 и 7?
Потому что типичная для Девопса диагностика выглядит так: 
3 - вообще вижу сервер?
4 - доступен нужный порт?
7 - приложение нормально отвечает?

- проверяем сетевую доступность
- проверяем порт
- проверяем само приложение
